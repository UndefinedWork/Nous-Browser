# 1.1.13 页面图标展示回归

版本：1.1.13（53）。验证日期：2026-11-02。

## 原因

标签行原本只画一次 favicon，随后原样显示网页标题。用户截图中的第二个星星是网页标题的前导 emoji。

检查 Zoom Canvas 当日发布的 [页面脚本](https://st1.zoom.us/zoom-docs/release/web/lynx/editor/assets/canvas.23572b97.js) 后确认：网站识别为 Safari 时跳过动态文档 favicon 更新，并把文档 emoji 加到 `document.title` 前面。1.1.12 的统一 WebKit 浏览器身份触发了该分支；因此蓝色站点图标和标题 emoji 同时出现。之前的动态 `rel=icon` 更新能力仍在，但此分支没有提供对应的动态图标声明。

## 修复边界

- 新增通用的标题展示元数据：只有“完整的单个前导 emoji + 水平空白 + 非空名称”才把 emoji 提升到唯一的图标位，配套名称去掉该前缀。
- 同时应用于展开标签、窄图标栏、拖拽预览和地址推荐（已打开标签及历史记录）。用户手动配置的快捷访问名称不做改写。
- 保留原始网页标题、窗口名称、搜索匹配和历史／会话文件；不修改网页 DOM、浏览器身份、网站 favicon 声明或 favicon 缓存。移除标题前缀后，继续显示网站提供的 favicon。
- 使用完整 Unicode 字素，保留 VS16、肤色、ZWJ、国旗和 keycap；普通数字、文本样式符号、正文中间的 emoji、无分隔前缀、孤立修饰符和半个国旗不提升。
- 不增加网页扫描、监听器、轮询、网络请求或网站域名特例。这是浏览器界面的展示兼容，不代表修改了网站本身的 favicon。
- emoji 文本使用自然字形尺寸，避免被 12 pt 图标占位的提议宽度截断；外部布局占位和行间距不变。
