# 1.1.4 下载保存框验证记录

版本：1.1.4（Build 44），Apple Silicon，macOS 26.0+。实测系统：macOS 26.7.2。

## 改动

- 原生 WebKit 右键菜单的 Download Video／Audio／Image／Linked File 不会经过普通导航下载回调。现在这些入口统一交给 Nous 的系统保存框，保留原有菜单的播放、复制、分享等操作。
- 对明确的右键下载，先选择文件名与位置，点击 Save 后才调用 WebKit 下载；取消不发起请求。没有改用独立网络会话，保留 WebKit 的 Cookie、重定向和 Blob 上下文。
- 普通附件和网页 download 链接在 WebKit 识别下载后选择位置；文件内容不会在确认前写入目标。此类请求需要先取得响应，不能保证请求本身始于 Save 之后。
- 原生媒体控件未发送 DOM 上下文时，使用同一次原生点击位置进行精确命中查询，只更新当前菜单；不会选择被遮挡或其他位置的媒体。导航、关闭菜单后迟到结果失效。
- 保存框共用队列，下载任务独立于标签生命周期。已确认的下载在来源标签关闭后继续；未确认的来源窗口关闭会取消选择。
- 先下载到所选目录的独立临时位置，完整成功后再替换目标；取消、失败保留已有文件。目标在下载期间已发生变化时拒绝替换。

## 自动化验证

- 完整 `swift test --no-parallel` 通过：应用 267 项／39 套件，MCP 8 项／3 套件；合计 275 项，270 通过、5 个原有密码事件循环测试按预期跳过，0 失败。
- 新增测试覆盖菜单分派、来源地址验证、媒体 currentSrc、同源 frame／Shadow DOM、遮挡与跨源拒绝、先确认后发请求、重复回调、取消、保存失败、覆盖冲突、文件名及扩展名。
- 此前与实机重启同时进行的并行测试出现既有 WebKit 启动、favicon 等待及自动化连接超时；停止实机操作后按顺序运行完整套件通过。未通过放宽超时或修改既有断言消除失败。
- Python 测试页编译与 HTTP 验证通过，涵盖生成的 PNG/WAV、Range、Cookie 验证、附件响应及故意截断的响应。已有 fixture 路由保留。
- Release 构建无编译警告或错误，`git diff --check` 通过。

## 实机验证

验证使用独立窗口和合成本地文件，不操作用户的真实视频或账户文件。可复用入口为 `python3 Tests/Fixtures/browser_test_server.py` 后访问 `/downloads`；视频使用本机另行生成的短 MP4。

- 实际右键 Download Video 显示系统保存框，改名后保存的 MP4 与源文件逐字节一致；没有第二次保存框。
- 最终安装版保存框等待超过 115 秒仍可操作。测试服务器在 Save 前只有播放器预加载的 1 次请求；点击 Save 后才增加第 2 次请求并成功保存。
- 图片右键下载显示保存框；Cancel 后无额外图片请求、无输出文件、无临时目录。再次 Save 后 PNG 与源图逐字节一致。
- 普通 download 属性链接可修改目录和文件名，保存内容一致；Blob 和 Cookie 验证附件在候选安装版保存成功。最终版普通附件覆盖测试通过。
- 明确下载链接选择已有测试文件并确认 Replace 后，模拟网络中断，实际显示 Download failed；原文件内容保持完整，临时目录被清理。随后正常附件下载替换同一文件，最终内容正确。
- 测试窗口已关闭，保存目录切回 Downloads，用户原有窗口保留。

音频菜单分派由自动化测试覆盖；当前系统的合成音频控件右键仅提供通用页面菜单，因此未宣称实机覆盖 Download Audio。此轮不宣称穷尽所有网站、DRM／流媒体下载、所有系统语言、跨窗口队列 UI 和 App Store 沙盒构建。
